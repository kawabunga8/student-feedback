# Assignment follow-up

One assignment, start to finish. The student-feedback app (http://127.0.0.1:8765, repo `~/Repos-folder/student-feedback`) already does the reading and posting safely; this skill is the order of work and the lessons learned. Scripts in `scripts/` (a read-only collector `assignment_collect.py`; two write tools, `teams_chat_send.py` and `onenote_write_pages.py`, that take an approved PLAN.json) run in the tools venv (`~/.venvs/student-feedback-tools/bin/python`) from the repo directory and use the app's signed-in Chrome profile, so close nothing else that holds the browser lock.

## Ground rules (why they matter)
- Anything students see or that changes a record (Teams return, MySchool save, chat, writing into a student's OneNote) is outward-facing. Show the exact recipients and exact wording and wait for a clear yes before each kind. Approval for one kind does not cover another.
- Never enter passwords. If Code.org, Teams or MySchool asks for sign-in, ask the user to sign in in the app's Chrome window and wait.
- Never delete (OneNote "Delete Page" is permanent). Tell the user which page to delete.
- Say plainly what was not read (private links, images, Canva bot checks) instead of implying it was checked.

## Steps
1. **Load the assignment in the app.** Pick it in the assignment menu. It must be linked to its Teams assignment: Choose from Teams -> List my assignments -> Read this assignment -> Import all assignment details -> Save. Saving a real change to instructions or criteria bumps the version and outdates review marks; spacing-only differences and Teams-link metadata no longer do.
2. **OneNote pages.** Setup -> Collect -> Collect whole class in the app lists each student's pages and matches by title. Anything not matched is "no page", not "no work": check the student's page list (blank "Untitled Page" entries sometimes hold only a link).
3. **Teams attachments and Code.org, in one Chrome session.** `scripts/assignment_collect.py OUT_DIR REQUEST.json` (request format is in its header) opens each student's panel on the To return and Returned tabs, clicks every attachment, converts SharePoint Word files to text (fetched with `?download=1` from inside the signed-in page), reads Word editor frames inline, screenshots Canva/Google (they render on a canvas), and, if `codeorg` is given, reads every roster student's lesson project for code length and last-saved. One launch replaces several: each Chrome start costs about a minute. Canva shows a "Verify you are human" check after repeat visits: never bypass it, tell the user. Code.org names differ from the roster (first names, nicknames, duplicate accounts like "Sam" and "Sam Example"): list the matches you assumed and confirm them. If Code.org needs sign-in, ask the user to sign in in the app's Chrome window (the script stops with that message).
4. **Reuse what you read.** Keep the OUT_DIR results and the Teams read for the whole session; do not re-read Teams for each step. Fixed pauses are a smell: wait for the thing you need.
5. **Document.** Build HTML and convert with `textutil -convert docx` (python-docx is not installed). Include a summary table and each student's work in full; replace any usernames or passwords with [removed]. Save in the assignment's Assessment folder. Make a separate completion checklist (student x OneNote / Teams attachment / Code.org / feedback sent) with totals and a still-to-do list.
6. **No-work feedback (only after approval).** In Draft & review use the toolbar button **No work found...**. It records an explicit *no submission* note on each ticked student (which sources you checked, and the date), keeps Work empty (Work is evidence, not feedback), and sets the level and comment you choose; no level is chosen for you, because lack of work does not by itself mean Emerging. It marks them reviewed; nothing is posted yet. Then Export & posting -> Post to all (Teams): tick the confirm box, "Post feedback and Return" (this returns the work and notifies students; the app reads each comment back). Then Save to MySchool (all): needs the assignment's `assignment_edit.php?exercise_id=...` address. MySchool sets status to Graded whenever a level is chosen, so "Set each student's status to Graded" is ticked by default and the preview says so; the app still verifies the final values, it does not accept any status.
7. **Chat messages (only after approval).** The Microsoft 365 chat connector may be blocked by the school's access policy (AADSTS53003); do not work around it. Write the approved recipients and exact text to a PLAN.json and run `scripts/teams_chat_send.py PLAN.json RESULT.json`. It uses Teams web in the app's Chrome: New message -> click the To box -> type the name -> accept only if exactly one result is a *Student* with that exact name -> send -> require the full approved text to appear one more time on the page. Anything else is SKIPPED or UNVERIFIED and is never repeated automatically (an unconfirmed send may have gone out). Put students who need two messages in one chat (two paragraphs).
8. **Pages in students' ClassNotebooks (only after approval).** `scripts/onenote_write_pages.py PLAN.json OUT_DIR` creates one titled page per listed student and saves a screenshot of each. It skips students who already have a matching page, requires the opened address to name the right student and section, waits for the page list to settle, and never deletes (OneNote's Delete Page is permanent: leave any duplicate for the teacher). Check each screenshot.

## Safety checks worth keeping
Read-back of every Teams comment, exactly-one-student matching for chats and MySchool, a current approval for the exact text before posting, and the explicit confirmation of recipients and wording. These cost little and prevent messages to the wrong student.

## Report back
Say what was sent where, per student, and what was skipped or unverified. Keep recipient lists and wording in the reply so the user can confirm them quickly.
